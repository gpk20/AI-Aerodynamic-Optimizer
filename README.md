# AI-Based Airfoil Aerodynamic Optimization Using Machine Learning

An end-to-end pipeline that predicts an airfoil's aerodynamic performance with machine learning, then uses a genetic algorithm to search for a better-performing shape -- and independently checks whether the result can actually be trusted.

## Problem

Designing an efficient airfoil normally means running expensive aerodynamic simulations one shape at a time, by hand, through trial and error. This project explores whether a machine learning model can learn the relationship between an airfoil's geometry and its aerodynamic performance well enough to guide an automated search for better designs -- turning airfoil design into a predict-generate-optimize-validate loop instead of manual iteration.

## Method

Geometry data for 1,664 real airfoils was pulled from the [UIUC Airfoil Coordinate Database](https://m-selig.ae.illinois.edu/ads/coord_database.html). Since that database only contains raw geometry (no performance data), [NeuralFoil](https://github.com/peterdsharpe/NeuralFoil) -- a neural network trained on tens of millions of real XFoil simulation runs -- was used to generate the missing performance labels: for every airfoil, CL and CD were computed across a grid of angles of attack and Reynolds numbers, producing a labeled training set of 133,120 rows. (One airfoil, a 3-element slotted high-lift system rather than a single continuous surface, was automatically excluded -- not every shape in the database is a single airfoil.)

Each airfoil is represented two ways: simple, interpretable shape descriptors (maximum thickness, maximum camber, and where each occurs along the chord) for the prediction model, and a compact 17-parameter CST/Kulfan parameterization for generating new shapes smoothly, without risking invalid or self-intersecting geometry.

## AI

Three regression models were trained to predict CL and CD from an airfoil's shape descriptors, angle of attack, and Reynolds number: Linear Regression, Random Forest, and Gradient Boosting (specifically `HistGradientBoostingRegressor`, for tractable training time on 130K+ rows).

| Model | CL error | CD error | CL R² | CD R² |
|---|---|---|---|---|
| Linear Regression | 16.1% | 64.2% | 0.88 | 0.258 |
| Random Forest | 3.5% | 15% | 0.99 | 0.897 |
| Gradient Boosting | 7.2% | 20.5% | 0.973 | 0.892 |

## Optimization

New airfoil shapes are generated by perturbing the 17-parameter CST representation of a baseline airfoil (NACA 2412), then evaluated directly with NeuralFoil -- no file I/O needed per candidate, which keeps the search fast. A genetic algorithm (population of 40, 30 generations, elitism + crossover + mutation) searches this shape space for higher L/D, subject to real engineering constraints:

- Thickness: 8%-18% of chord
- Camber: 0%-6% of chord
- Minimum CL: 0.6 at the design point

The optimizer's best result from a NACA 2412 baseline: a shape with **11.7% max thickness and 5.8% max camber** -- notably, camber landed right at the edge of the allowed 6% limit, which is what a constrained search is supposed to do when more camber genuinely helps.

## Validation

The optimizer only ever asked one source of truth whether a shape was good: NeuralFoil, evaluated directly on that exact shape. To check that result independently, a second model was trained from scratch on the full dataset (never shown the optimized shape specifically) and its predictions were compared against NeuralFoil's direct evaluation:

- **CL disagreement: 7.5%** -- solid agreement, a good sign the lift prediction is trustworthy
- **CD disagreement: 23.6%** (absolute: 0.0045) -- a real but explainable amount of uncertainty, concentrated at the edge of the camber constraint where the model is more likely extrapolating
- **NeuralFoil's own reported confidence on this shape: 0.890**

This isn't a substitute for running the optimized shape through real XFoil or a wind tunnel, but it's a meaningfully more rigorous check than just trusting the optimizer's own headline number.

## Limitations

- **Single-point optimization**: the optimizer was only scored at one angle of attack. [FILL IN: once compare_designs.py has been run, note here whether/where the optimized shape underperforms the baseline across the rest of the angle-of-attack sweep -- this is a genuine, worth-reporting tradeoff, not a flaw in the code.]
- **Surrogate-model dependence**: every prediction in this project ultimately traces back to NeuralFoil, itself a neural network approximation of XFoil rather than ground truth. The independent-model check in Validation partially addresses this, but doesn't replace a real aerodynamic simulation or wind-tunnel data.
- **2D sectional analysis only**: this models airfoil sections, not full 3D wings -- no span, taper, sweep, or induced drag effects are captured.
- **Geometry edge cases**: a small number of raw UIUC `.dat` files (e.g. multi-element high-lift systems) aren't single continuous airfoils and are automatically filtered out rather than handled.

## Future work

- Optimize across multiple angles of attack simultaneously (e.g. average L/D over a flight-relevant range) rather than a single design point, to avoid the tradeoff found above
- Validate the optimized shape against real XFoil output or published wind-tunnel polar data directly, rather than only a second ML model
- Extend from 2D sections to a full 3D wing model
- Build an interactive interface (e.g. Streamlit) so a target CL, Reynolds number, and constraints can be entered directly and the optimizer run on demand

## Project structure

```
AI-Aerodynamic-Optimizer/
├── airfoils/                  # raw UIUC geometry files (gitignored -- download separately)
├── generate_dataset.py        # Phase 3+4: geometry -> labeled performance dataset
├── train_model.py             # Phase 5+6: train and compare CL/CD prediction models
├── generate_airfoils.py       # Phase 7: random airfoil shape generation (CST/Kulfan)
├── optimize_airfoil.py        # Phase 8+9: genetic algorithm optimizer with constraints
├── compare_designs.py         # Phase 10: baseline vs optimized, swept across angle of attack
├── validate_optimized.py      # Phase 11: independent second-model validation check
├── requirements.txt
└── README.md
```

## Setup

```
pip install -r requirements.txt
```

Download airfoil geometry files from the [UIUC Airfoil Database](https://m-selig.ae.illinois.edu/ads/coord_database.html) (the "coord_seligFmt.zip" link gets all ~1,600 at once) into an `airfoils/` folder, then run the scripts in order: `generate_dataset.py` → `train_model.py` → `generate_airfoils.py` → `optimize_airfoil.py` → `compare_designs.py` → `validate_optimized.py`.
